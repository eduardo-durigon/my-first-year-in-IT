## Labs and Practical Skills

### Lab 10 – Introduction to Active Directory

The biggest practical achievement this week was starting **Lab 10 – Introduction to Active Directory** in my GitHub troubleshooting repository.

The objective of this lab is to build a realistic Windows Server environment and gain hands-on experience with Active Directory Domain Services (AD DS).

Active Directory is an important technology in many organizational Windows environments, and I wanted to understand how it works by building my own domain from scratch.

I started by configuring Hyper-V on my Windows 11 Pro laptop and creating a dedicated internal virtual network for the lab.

I then created a virtual machine running **Windows Server 2025 Standard Evaluation**.

The initial configuration involved:

* Creating and configuring the Windows Server virtual machine.
* Configuring a dedicated Hyper-V Internal Virtual Switch.
* Establishing a separate IP addressing scheme for the lab network.
* Configuring a static IPv4 address for the server.
* Renaming the server to `EDU-DC01`.
* Installing the Active Directory Domain Services role.
* Configuring DNS as part of the domain controller deployment.
* Creating a new Active Directory forest and domain named `ad.lab`.
* Successfully promoting the server to a Domain Controller.

After completing the installation, I restarted the server and successfully logged in using the domain Administrator account.

I also verified that the server was correctly operating as a Domain Controller for the new `ad.lab` domain.

This was an important milestone because I now have a functioning Active Directory environment that I can use to practise Windows domain administration.

The lab is still ongoing, and there is plenty more to do.

My next objectives include creating Organizational Units (OUs), managing test user accounts, creating security groups, and exploring basic user administration.

After that, I plan to create a Windows 11 client virtual machine, join it to the domain, and practise domain authentication.

I am documenting the process in my existing GitHub repository:

https://github.com/eduardo-durigon/endpoint-troubleshooting-labs

The goal is to build a collection of practical exercises that demonstrate my ability to configure systems, investigate problems, and work with technologies relevant to IT Support.

## Key Takeaways

The biggest takeaway this week is the importance of combining theoretical knowledge with practical experience.

Studying the OSI model helps me understand how network communication works, but configuring an actual network environment gives me an opportunity to apply those concepts.

Reading about PowerShell is useful, but actually working with commands and understanding their output is what will help me develop practical skills.

The same applies to Active Directory.

There is a significant difference between knowing what a Domain Controller does and actually installing Windows Server, configuring a domain, and successfully promoting a machine to become a Domain Controller.

Building the environment myself has already given me a much better appreciation of the different components involved, particularly Hyper-V, networking, DNS, Windows Server, and Active Directory.

Another important point is that I don't need to rush through these exercises.

I want to understand what I'm configuring, why I'm doing it, and how the knowledge relates to real IT Support responsibilities.

My priority remains developing the confidence and practical ability to handle common technical tasks in a professional environment.
