## Labs and Practical Skills

### Lab 10 – Introduction to Active Directory

This week, I completed **Lab 10 – Introduction to Active Directory**, bringing my foundational Windows Server and Active Directory project to completion.

The lab was built using Hyper-V on my Windows 11 Pro host and involved deploying Windows Server 2025, configuring Active Directory Domain Services, establishing the `ad.lab` domain, and creating a Windows 11 client to practise domain administration and authentication.

Throughout the project, I gained hands-on experience with several fundamental Windows domain administration tasks.

Some of the tasks I completed included:

* Installing and configuring Windows Server 2025.
* Deploying Active Directory Domain Services and promoting the server to a Domain Controller.
* Configuring DNS and understanding its relationship with Active Directory.
* Creating and organizing Organizational Units.
* Creating and managing domain user accounts and security groups.
* Configuring static IP addressing within an isolated virtual network.
* Joining a Windows 11 client to the domain.
* Testing domain authentication using different user accounts.
* Configuring shared network folders and departmental access.
* Applying NTFS permissions and understanding share permissions.
* Managing permission inheritance and group-based access control.
* Testing access restrictions using different domain accounts.
* Creating a dedicated domain administrator account.
* Practising User Account Control (UAC) and administrative elevation.
* Performing password resets and enabling and disabling domain accounts.
* Practising basic domain account troubleshooting.

One of the most useful parts of the lab was configuring shared network folders and applying permissions through Active Directory security groups.

I created separate IT and HR shared folders, configured their permissions, and tested access using different domain accounts.

This allowed me to verify that users could access the resources assigned to their respective departments while being denied access to the other department's folders.

I also encountered and investigated problems during the lab, including DNS resolution issues and memory limitations when running virtual machines simultaneously.

Troubleshooting the DNS issue helped me understand forward and reverse lookups, PTR records, and how Active Directory relies on DNS to locate domain services.

I also investigated hardware-reserved memory on my host machine and made a BIOS configuration adjustment that recovered several gigabytes of memory, improving the available resources for running my virtual machines.

Completing this lab gave me a much better understanding of how different Windows Server components interact within a domain environment.

More importantly, it allowed me to practise these tasks rather than simply reading about them.

The foundational objectives of the lab are now completed. I may revisit some of these areas in future projects, particularly Group Policy, additional administration tasks, and PowerShell automation, but I want to keep those topics separate rather than expanding this introductory lab indefinitely.

This project builds upon the traditional Active Directory experience developed in Lab 10 and introduces cloud-based identity management and Microsoft 365 administration.

The objective is to build and manage a small-business cloud environment, practise everyday administrative tasks, and understand how modern organizations manage cloud identities, authentication, email, collaboration, and access to resources.

I started by establishing a Microsoft 365 personal environment and practising the use of Microsoft applications and cloud storage.

Some of the tasks completed included:

* Installing and configuring Microsoft 365 desktop applications.
* Configuring Outlook.
* Verifying Microsoft account authentication.
* Sending and receiving test emails.
* Adding multiple email accounts and accessing different inboxes.
* Inspecting OneDrive account configuration.
* Creating a dedicated OneDrive test folder.
* Testing local-to-cloud file synchronization.
* Verifying files through OneDrive web.
* Testing cloud-to-local synchronization.

After completing the initial personal environment setup, I moved on to investigating and establishing the business environment for the project.

I explored Microsoft 365 Business subscriptions, Microsoft Entra ID licensing, trial options, available sandbox environments, and the Microsoft 365 Developer Program to determine the most suitable environment for practising administration.

I also began working with the foundational concepts and administrative tasks associated with Microsoft Entra ID.

This included:

* Understanding tenants and cloud identities.
* Exploring the differences between Microsoft Entra ID and traditional Active Directory.
* Creating and managing cloud users.
* Disabling, deleting, and restoring accounts.
* Resetting passwords and managing user properties.
* Creating security groups and managing group membership.
* Understanding administrative roles.
* Exploring multifactor authentication (MFA) and authentication methods.

This project is particularly important because Microsoft 365 and cloud identity services are widely used in modern business environments.

I want to develop a better understanding of how user accounts, authentication, permissions, and cloud services are managed, as well as how these services relate to the traditional Windows domain environments I have been practising.

The initial phases of the project are now completed, and the next stage will focus on Microsoft 365 service administration, including Exchange Online, Teams, SharePoint, OneDrive administration, licensing, and the integration between these services.
